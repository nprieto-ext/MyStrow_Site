Vos lumières
répondent à tout le reste

MyStrow ouvre une API HTTP dès son lancement. Une box domotique, un Stream Deck, un script ou une tâche planifiée peuvent alors lancer une mémoire, un effet, une couleur ou un noir, sans toucher à la console.

Par MyStrow · Publié le 19 novembre 2026 · ⏱ Lecture : 7 min
Voir les commandes → Domotique et KNX →
Le principe

Une adresse, des commandes simples

Au démarrage, MyStrow ouvre une petite porte d'entrée sur l'ordinateur : http://127.0.0.1:8765/api/. N'importe quel programme installé sur ce même ordinateur peut y envoyer une commande, et MyStrow l'exécute exactement comme si vous aviez appuyé sur le pad de l'AKAI.

Les commandes tiennent dans l'adresse elle-même. Pour lancer la mémoire 1.1 : une requête POST vers /api/memory/1.1. Pour faire le noir : POST /api/blackout. Les réponses sont en JSON, ce que savent lire tous les outils d'automatisation.

Il n'y a rien à activer. MyStrow doit simplement être ouvert, avec votre show chargé.

Nouveau dans la 3.2.20 : l'accès par le réseau local. Une case dans Connexion › Contrôle › API réseau rend l'API joignable depuis les autres appareils du réseau (box domotique, serveur, tablette), protégée par une clé. Voir plus bas.

💻 Windows et Mac 🎛 MyStrow 3.2.9 et supérieur 🌐 Réseau local avec clé : 3.2.20
À quoi ça sert

Quatre façons de s'en servir

🏠

Domotique et installations fixes

Bar, salle des fêtes, maison équipée : un bouton KNX « mode fête » lance l'ambiance, un autre remet l'éclairage normal. Le client n'ouvre jamais MyStrow.

🎛

Stream Deck et boutons programmables

Une touche par mémoire, une touche pour le noir, une pour l'effet stroboscope. Idéal en régie de streaming ou à côté d'une table de mixage.

⏰

Ambiances programmées

Avec le planificateur de tâches de Windows : la vitrine passe en ambiance chaude à 18 h, en noir à 23 h, tous les jours, sans personne.

🧩

Vos propres outils

Un script Python, une application maison, un automate de spectacle : tout ce qui sait envoyer une requête HTTP peut piloter vos lumières.

Référence

Les commandes

Toutes les adresses commencent par http://127.0.0.1:8765 sur le PC lui-même, ou par http://<IP-du-PC>:8765 depuis le réseau (avec la clé). Les commandes qui agissent sont en POST, celles qui lisent l'état sont en GET.

CommandeCe qu'elle faitExemple
POST /api/memory/{c.r}Lance une mémoire, de 1.1 à 8.8 (colonne.rangée)./api/memory/2.3
POST /api/effect/{nom}Lance un effet par son nom (majuscules indifférentes), ou bascule un bouton d'effet de 0 à 7./api/effect/Strobe%20Classique
POST /api/speed/{0-100}Vitesse des effets./api/speed/70
POST /api/stop_effectsCoupe tous les effets en cours.
POST /api/level/{fader}/{0-100}Niveau d'un fader de groupe, de 0 à 7 (le premier fader est le 0). Accepte aussi +10 ou -10./api/level/0/80
POST /api/mute/{fader}/{0|1}Coupe (1) ou rétablit (0) un fader./api/mute/3/1
POST /api/projectorsCouleur, niveau, strobe ou coupure de projecteurs précis. Corps JSON, voir l'exemple plus bas.
POST /api/blackoutNoir complet : faders, effets et strobe.
POST /api/play · /next · /prevLecture/pause, média suivant, média précédent de la playlist.
POST /api/goto/{ligne}Lance une ligne précise de la playlist (la première est la 0)./api/goto/4
POST /api/cartouche/{0-3}Déclenche une des quatre cartouches./api/cartouche/0
POST /api/go · /gobackMémoire suivante ou précédente en mode GO.
GET /api/stateÉtat complet en cours.
GET /api/memoriesLes 64 mémoires : enregistrée ou vide, active ou non, couleur.
GET /api/effectsLa liste de vos effets, y compris ceux que vous avez créés.
GET /api/sequences · /cartouchesLe contenu de la playlist et des cartouches.

Une erreur ne passe pas en silence. Une commande mal formée ou un nom d'effet inconnu renvoie un code d'erreur avec un message clair (« Effet inconnu : … (voir GET /api/effects) »). Votre automate sait donc si la commande a vraiment été exécutée.

Premier essai

Tester en trente secondes

Ouvrez MyStrow avec votre show, puis l'invite de commandes de Windows (ou le Terminal sur Mac). L'outil curl y est déjà installé.

1

Lancer une mémoire

curl -X POST http://127.0.0.1:8765/api/memory/1.1
MyStrow répond {"ok": true} et la mémoire 1.1 s'allume, sur les projecteurs comme sur l'écran.

2

Lancer un effet par son nom

curl -X POST http://127.0.0.1:8765/api/effect/Strobe%20Classique
Les espaces du nom s'écrivent %20. La liste exacte de vos effets : curl http://127.0.0.1:8765/api/effects.

3

Mettre des projecteurs en couleur

Dans PowerShell, pour passer les deux premiers projecteurs du patch en bleu :
Invoke-RestMethod -Method Post -Uri http://127.0.0.1:8765/api/projectors -ContentType "application/json" -Body '{"events":[{"type":"proj_color","idxs":[0,1],"color":"#0040ff"},{"type":"proj_level","idxs":[0,1],"value":100}]}'
Les projecteurs sont numérotés dans l'ordre du patch, le premier est le 0.

4

Faire le noir

curl -X POST http://127.0.0.1:8765/api/blackout

Le conseil qui simplifie tout : préparez vos ambiances en mémoires dans MyStrow (couleurs, effets, lyres), puis ne faites appeler que des mémoires par l'extérieur. Vous réglez l'ambiance une fois, à l'œil, et la domotique se contente de dire « mémoire 1.1 ».

Installation fixe

Un « mode fête » sur un bouton KNX

Le cas typique : un intégrateur équipe une salle ou une maison de projecteurs DMX, pilotés par MyStrow sur un mini-PC. Le client, lui, veut seulement appuyer sur un bouton de sa domotique pour passer en mode fête, choisir une couleur ou tout éteindre.

Dans tous les cas, commencez par enregistrer une mémoire par scénario dans MyStrow : 1.1 = mode fête, 1.2 = ambiance douce, 1.3 = blanc chaud… La domotique n'aura qu'à appeler la bonne mémoire, ou /api/blackout pour tout éteindre. Faites aussi démarrer MyStrow avec Windows (raccourci dans le dossier Démarrage) : le PC redémarre, les lumières restent pilotables.

Méthode directe : l'API réseau (MyStrow 3.2.20 et plus)

1

Ouvrir l'API au réseau local

Dans MyStrow : Connexion › Contrôle › API réseau, cochez « Autoriser l'accès depuis le réseau local ». La fenêtre affiche l'adresse à utiliser (par exemple http://192.168.1.50:8765/api/) et la clé. Si Windows demande l'autorisation du pare-feu, acceptez pour les réseaux privés.

2

Envoyer la clé avec chaque requête

Au choix : l'en-tête Authorization: Bearer <clé>, l'en-tête X-API-Key: <clé>, ou ?key=<clé> à la fin de l'adresse. Sans la bonne clé, MyStrow répond 401 et n'exécute rien.

3

Exemple avec Home Assistant

Dans configuration.yaml, une commande par scénario :
rest_command:
  mystrow_fete:
    url: "http://192.168.1.50:8765/api/memory/1.1"
    method: POST
    headers:
      Authorization: "Bearer VOTRE_CLÉ"
Appelez ensuite rest_command.mystrow_fete depuis une automatisation, un bouton du tableau de bord ou un appui KNX remonté dans Home Assistant.

4

Tester depuis le bouton

Un appui, et l'ambiance part. Le retour d'état (une LED sur le bouton, par exemple) peut se faire en lisant GET /api/memories, avec la clé lui aussi.

Une clé compromise ? Le bouton « Nouvelle clé » de la même fenêtre en crée une autre : l'ancienne cesse aussitôt de fonctionner. Sur le PC lui-même, aucune clé n'est demandée : le Stream Deck et l'extension Claude continuent de marcher sans rien changer.

Autre méthode : Node-RED sur le PC de MyStrow

Avec une version de MyStrow antérieure à la 3.2.20, ou si vous préférez garder l'API fermée au réseau, installez un traducteur sur le même PC que MyStrow. Node-RED, gratuit, est parfait pour ça : il existe des modules KNX/IP prêts à l'emploi (par exemple node-red-contrib-knx-ultimate).

1

Installer Node-RED sur le même PC

Ajoutez-y un module KNX, configuré sur votre passerelle KNX/IP. Créez une adresse de groupe par scénario dans ETS.

2

Relier chaque adresse à une commande

Pour chaque scénario : un nœud KNX qui écoute l'adresse de groupe, suivi d'un nœud http request en POST vers http://127.0.0.1:8765/api/memory/1.1. Pour l'arrêt, la même chose vers /api/blackout.

Si votre box (Home Assistant, Jeedom, serveur logique) est sur une autre machine, Node-RED sur le PC de MyStrow sert de relais : un nœud http in reçoit la requête de la box par le réseau, un nœud http request la transmet à MyStrow.

💡 Et le Raspberry Pi ? MyStrow fonctionne sur Windows et sur Mac, pas encore sur Raspberry. Pour une installation fixe, un mini-PC Windows sans ventilateur, branché sur l'interface DMX, est discret et fiable.

Sans programmer

Stream Deck et tâches planifiées

🎛 Stream Deck

Installez depuis le store d'Elgato un plugin qui envoie des requêtes HTTP (« API Ninja », par exemple). Chaque touche reçoit une adresse : POST http://127.0.0.1:8765/api/memory/1.1, /api/blackout, /api/next…

⏰ Planificateur de tâches

Dans Windows, créez une tâche qui démarre à l'heure voulue, avec comme programme curl.exe et comme arguments -X POST http://127.0.0.1:8765/api/memory/1.2. Une tâche par ambiance.

À savoir

Ce que l'API ne fait pas

  • Elle n'est pas sur Internet. Par défaut, elle n'écoute que sur l'ordinateur (127.0.0.1). Ouverte au réseau local (3.2.20), elle exige une clé de chaque appareil. Ne l'exposez pas sur Internet en ouvrant un port de votre box.
  • Une page web ne peut pas faire le noir. Les commandes sensibles (noir, projecteurs, vitesse, arrêt des effets) sont refusées quand elles viennent d'un navigateur.
  • Elle ne modifie pas votre show. Aucune commande n'efface une mémoire, ne touche au patch ou à vos réglages : seulement des commandes de jeu.
  • MyStrow doit être ouvert. Si le logiciel est fermé, la commande n'aboutit pas : votre automate reçoit une erreur de connexion.
